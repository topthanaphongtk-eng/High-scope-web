# Database — schema reference

Two equivalent schemas live here:

| File | Engine | Purpose |
|---|---|---|
| `schema_sqlite.sql` | SQLite | What the desktop app builds at runtime (single-file DB, fast local writes). |
| `schema_mssql.sql`  | MS SQL Server | Same shape adapted for SQL Server — for the team's central DB / web monitor. |

Both are kept **in sync by design** — adapter changes (Python's `CaptureDB`) write the same fields under the same names; the only differences are dialect-level (data types, identity vs autoincrement, index syntax).

The schema covers **fused image captures only** — there is no measurement / analysis data. Each Confirm event in the desktop app produces 1 row in `captures` plus 1–3 rows in `capture_files` depending on the chosen mode.

---

## Tables

### `captures` — one row per Confirm & Save action

| Column | Type (MSSQL) | Type (SQLite) | Notes |
|---|---|---|---|
| `capture_id`     | `UNIQUEIDENTIFIER` PK | `TEXT` PK | UUID generated by the desktop client |
| `confirmed_at`   | `DATETIME2(3)` | `TEXT` (ISO 8601) | When the operator clicked Confirm |
| `lot_id`         | `NVARCHAR(64)` | `TEXT` | LOT ID typed/scanned at sign-in |
| `bonding_number` | `NVARCHAR(64)` | `TEXT` | From MES `LotDetail.Bonding_Running` |
| `lot_location`   | `NVARCHAR(64)` | `TEXT` | From MES `LotDetail.LotLocation` (machine / station) |
| `mpc`, `package`, `qs` | `NVARCHAR(64)` | `TEXT` | Lot context fields from MES |
| `operator_badge` | `NVARCHAR(32)` | `TEXT` | e.g. `B19277` |
| `hostname`       | `NVARCHAR(128)` | `TEXT` | Machine that wrote the row |
| `app_version`    | `NVARCHAR(32)` | `TEXT` | Desktop app version |
| `mode`           | `NVARCHAR(16)` | `TEXT` | `mode1` (single fuse) or `mode2` (Ball+Pad+Weld) |
| `raw_lot_info`   | `NVARCHAR(MAX)` | `TEXT` | JSON dump of full MES `LotDetail` |

Indices:
- `(lot_id, confirmed_at DESC)`
- `(bonding_number, lot_location, confirmed_at DESC)`
- `(confirmed_at DESC)`

### `capture_files` — one row per fused image saved

Many-to-one to `captures` via `capture_id`. Mode 1 has 1 file row, Mode 2 has 3 (Ball / Pad / Weld).

| Column | Type (MSSQL) | Type (SQLite) | Notes |
|---|---|---|---|
| `id`             | `BIGINT IDENTITY(1,1)` PK | `INTEGER PRIMARY KEY AUTOINCREMENT` | |
| `capture_id`     | `UNIQUEIDENTIFIER` FK | `TEXT` | → `captures.capture_id` |
| `slot`           | `NVARCHAR(32)` | `TEXT` | `image` / `Ball` / `Pad` / `Weld` |
| `fused_path`     | `NVARCHAR(512)` | `TEXT` | Full path to fused TIFF in share folder |
| `fused_name`     | `NVARCHAR(256)` | `TEXT` | Filename only |
| `size_bytes`     | `BIGINT` | `INTEGER` | File size |
| `sha256`         | `NVARCHAR(64)` | `TEXT` | Hex digest, NULL if SHA disabled |

Indices:
- `(capture_id)` — for fast lookup of a capture's files

## File naming convention

Fused TIFFs are written to:
```
{shared_root}/{YYYY}/{MM}/{lot_id}/<filename>.tif
```
plus a sidecar `.json` with metadata (operator, OME-XML, etc.).

The `<filename>` follows:
- **Mode 1** (slot = `image`): `{LOT}_{Badge}_{LotLocation}_{TS}_{Host}.tif`
- **Mode 2**: `{LOT}_{Badge}_{LotLocation}_{Slot}_{TS}_{Host}.tif`

The desktop app also mirrors a per-capture record JSON to `{lot_dir}/_records/{capture_id}.json` so a web crawler can scan the share folder without touching the DB.

---

## Storing values: convention

* Timestamps are **ISO 8601 with timezone offset** in SQLite, native `DATETIME2` in SQL Server.
* `raw_lot_info` stores the entire upstream MES record verbatim — schema evolution doesn't break old data.

---

## Bringing data over

The desktop app currently writes to SQLite. To seed SQL Server:

1. **Run the schema:** `sqlcmd -S server -d HighScope -i schema_mssql.sql`
2. **Export current SQLite data:** `python tools/export_to_csv.py`
3. **Import the two CSVs** with SSMS Import Wizard, BULK INSERT, or `bcp`:
   ```sql
   BULK INSERT dbo.captures
       FROM 'C:\path\to\captures.csv'
       WITH (FIRSTROW=2, FIELDTERMINATOR=',', CODEPAGE='65001', FORMAT='CSV');
   BULK INSERT dbo.capture_files
       FROM 'C:\path\to\capture_files.csv'
       WITH (FIRSTROW=2, FIELDTERMINATOR=',', CODEPAGE='65001', FORMAT='CSV');
   ```

Encoding: CSVs are UTF-8 with BOM, NULLs are empty cells, datetimes ISO 8601.
